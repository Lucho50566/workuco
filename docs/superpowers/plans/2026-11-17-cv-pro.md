# CV Pro Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Servicio pago "Mejorá tu CV con IA" ($ 5.000): análisis gratis, vista previa recortada, pago con Mercado Pago y CV completo en uno de 6 diseños.

**Architecture:** Lógica pura en `lib/cvpro.js` (listas fijas, prompts, validación anti-invención, recorte de la vista previa, IA simulada); datos en `lib/store.js` (`cv_orders`, `payments` generalizado); rutas en `server.js`; página `public/cv-pro.html` + `public/cvpro.js` + `public/cvpro.css`.

**Tech Stack:** Node 24 sin dependencias, `node:sqlite`, JS/CSS sin framework, IA del servidor (`ai.importConfig()` + `ai.callProvider`), Mercado Pago (`lib/mp.js`).

**Spec:** `docs/superpowers/specs/2026-11-17-cv-pro-design.md`

## Global Constraints

- Sin dependencias nuevas. Español rioplatense en todo texto visible.
- IA: `ai.importConfig()`; sin config y sin `WORKUCO_IMPORT_AI_FAKE=1` → servicio apagado (meta `cvPro.enabled=false`, API 503).
- Precio por defecto **5000** ARS (`admin_meta.price_cv`); "Vender CV Pro" = `admin_meta.sell_cv === '1'`; activo sólo si además `mp.connected()` y `mp.isPublicHttps(PUBLIC_URL)` (para cobrar). Análisis y vista previa funcionan aunque el cobro no esté activo; el botón de pagar sólo aparece si está activo.
- Diseños: `clasico, moderno, campo, servicio, creativo, primer-empleo`. Acentos: `verde #0a8263, malbec #7a1f4d, azul #1f4e79, terracota #b5521b, grafito #2d2d2d, uva #5b4fa3`. Secciones: `resumen, experiencia, estudios, habilidades, idiomas, cursos, logros, voluntariado, disponibilidad, referencias`.
- Límites: 3 análisis por día por cuenta (día AR); 3 versiones antes de pagar (la primera incluida); 3 reescrituras después de pagar; PDF ≤ 5 MB; ≤ 3 fotos; texto ≤ 60.000 caracteres.
- El archivo subido no se guarda (texto extraído sí). Consentimiento `consent: true` obligatorio.
- Sólo sesión de persona (`me.role === 'candidate'`); cada orden sólo la ve su dueña (404 a otros) y el admin.

## Review Focus

1. Persona que entra al CV de otra (`/api/cvpro/:id` ajeno) → 404, nunca contenido.
2. Vista previa: la respuesta JSON sin pagar **no contiene** los bullets ocultos (ni en otro campo).
3. IA devuelve JSON roto o con empresas/estudios que no estaban → no se rompe; se descartan y la orden queda usable.
4. Pago aprobado de CV que vuelve por la misma ruta que destacados → la orden queda pagada una sola vez y no toca avisos.
5. PDF escaneado sin texto → 400 con mensaje "Subí fotos de tu CV", sin gastar IA.

### Task 1: Lógica pura `lib/cvpro.js`

**Files:** Create `lib/cvpro.js`, Test `tools/test-cvpro-lib.js` (agregar a `npm test`).

**Interfaces — Produces:**
- `DESIGNS: string[]`, `ACCENTS: {id,hex,label}[]`, `SECTIONS: string[]`, `CHECKS: {id,label}[]` (contacto, titular, resumen, experiencia, fechas, logros, estudios, habilidades, idiomas, movilidad, disponibilidad, referencias, largo, redaccion, foto).
- `analyzePrompt({ text, profile }) → { system, user }`; `generatePrompt({ extracted, inputs, request }) → { system, user }` (ambos piden SÓLO JSON y prohíben inventar hechos).
- `normalizeAnalysis(raw) → { score:0..100 int, rubro:string, checks:[{id,label,status:'ok'|'falta'|'mejorable',note}] (uno por CHECKS, en orden), suggestions:string[≤8], extracted:{ name, headline, contact{phone,email,locality}, summary, experience[{company,role,from,to,tasks[]}], education[{institution,title,year}], skills[], languages[{name,level}], extras{} } }`.
- `allowedCorpus(...texts) → string` (normalizado sin tildes, minúsculas).
- `normalizeCv(raw, corpus) → cv` con `design∈DESIGNS` (si no, `clasico`), `accent∈ids` (si no, `verde`), `sections` filtradas a SECTIONS sin repetidos (si vacía, orden por defecto), largos topeados (headline 90, summary 600, bullet 180, ≤6 bullets, ≤6 experiencias), y **descarta** experiencias cuya `company` o `role` y estudios cuya `institution` no aparezcan en `corpus`.
- `previewCv(cv) → cv` recortado: completos `name, headline, contact, summary, experience[0]`; resto de experiencias con `bullets` = `[primer bullet, '▇▇▇▇▇▇▇▇▇▇▇▇']`; `education/skills/languages` sólo los 2 primeros + marca `locked: true`.
- `fakeAnalysis(text)` y `fakeCv(extracted)` para pruebas (usan datos del texto, nada inventado).

- [ ] Test (falla): `normalizeAnalysis({score:140,checks:[{id:'resumen',status:'x'}]})` → `score===100`, 15 checks, el de resumen con `status==='falta'`; `normalizeCv({design:'raro',accent:'rosa',sections:['resumen','resumen','hackeo'],experience:[{company:'Bodega Inventada',role:'CEO'},{company:'Finca Los Nogales',role:'Podador',bullets:['a','b','c']}]}, allowedCorpus('Finca Los Nogales podador'))` → `design==='clasico'`, `accent==='verde'`, `sections` sin repetidos ni `hackeo`, una sola experiencia (Los Nogales); `previewCv` de un CV con 3 experiencias de 4 bullets → `JSON.stringify` no contiene el tercer bullet de la segunda experiencia.

### Task 3: API y cobro (`server.js`, `lib/mp.js`)

**Interfaces — Consumes:** Task 1 y 2, `ai.importConfig/callProvider/parseJson`, `extractCv`/`extractPdf`, `mp.*`, `settlePayment`.
**Produces (rutas, todas JSON):**
- `GET /api/meta` → `cvPro: { enabled, price, canPay }`.
- `POST /api/cvpro/analyze` `{ source:'pdf'|'fotos'|'perfil', pdf?:{name,data(base64)}, photos?:dataUrl[], consent:true }` → `201 { order }`. Errores: 401 sin persona, 400 sin consent / PDF sin texto ("Subí fotos de tu CV") / >3 fotos, 413 PDF > 5 MB, 429 cuarto análisis del día, 503 sin IA.
- `POST /api/cvpro/:id/generate` `{ inputs?:{...}, request?:string(≤300) }` → `{ order }` con `cv` recortado si no está pagado; 400 al superar 3 versiones antes de pagar.
- `GET /api/cvpro` → `{ orders }` propias; `GET /api/cvpro/:id` → `{ order }` (recortado si no pagado); ajena → 404.
- `PATCH /api/cvpro/:id/style` `{ design?, accent? }` (validados) → `{ order }`.
- `POST /api/cvpro/:id/rewrite` `{ request }` → sólo pagado, descuenta `rewritesLeft` (400 en 0).
- `POST /api/cvpro/:id/checkout` → `{ url }` (precio de la orden; 400 si no hay CV generado o cobro inactivo; 409 si ya pagado).
- `settlePayment`: según `row.kind`: `cv` → `updateCvOrder(ref,{status:'pagado',paymentId,paidAt})` + notificación a la persona; destacados sin cambios. `POST /api/company/payments/confirm` sigue para empresas; nueva `POST /api/cvpro/payments/confirm {paymentId}` para personas (misma verificación de dueño).
- `mp.createPreference({..., returnPath})` → back_urls `${publicUrl}${returnPath}?pago=ok|pendiente|error` (destacados `/panel`, CV `/cv-pro/<id>`).
- `PUT /api/admin/payments/settings` acepta `cvPrice` (100…10.000.000) y `sellCv`; `GET /api/admin/payments` devuelve `settings.cvPrice, settings.sellCv` y `kind` por pago.
- Página: `GET /cv-pro` y `/cv-pro/:id` → `renderPage('cv-pro.html')`.

- [ ] Test `tools/test-cvpro.js` (falla primero), servidor con `WORKUCO_IMPORT_AI_FAKE=1` y Mercado Pago simulado (como `test-pagos.js`): 401/400/429/503 de arriba; PDF de texto → `order.analysis.checks.length===15`; generar → `order.cv.design∈DESIGNS` y el JSON no trae el bullet oculto; otra persona → 404; 4ª versión antes de pagar → 400; checkout → preferencia con `unit_price===5000`, `back_urls.success` termina en `/cv-pro/<id>?pago=ok`; webhook aprobado firmado → orden `pagado`, `GET` devuelve CV completo, ningún aviso cambia `featured`; repetir webhook no duplica; reescritura con `rewritesLeft` 3→2; admin cambia `cvPrice` a 6000 → orden nueva cobra 6000 y la vieja sigue en 5000; borrar cuenta → sus órdenes desaparecen.
- [ ] Implementar. `npm test` completo. Commit.
